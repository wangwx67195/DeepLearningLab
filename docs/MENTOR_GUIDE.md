# 导师操作手册

更新：2026-10-28。用途：帮助本地Agent备课、提示、审阅并维护事实记录。约束以根目录AGENTS.md和学生最新指示为准；课程路线看LEARNING_PLAN.md，实际进度只看PROGRESS.md。本文不复制一份当前章节表。

## 1. 恢复课程

1. 读取AGENTS.md、PROGRESS.md当前位置及最后一条实际Session；模板不算Session。
2. 读取LEARNING_PLAN.md对应主题，以及学生本课现有代码；迁移路径查lessons/INDEX.md。
3. 简短说明“当前主题、已通过范围、仍需做的最小一步”。查看文件后再判断缺什么，不能默认空目录或沿用聊天中的旧代码。
4. 需要执行时才核实解释器/依赖/设备。历史GPU结果不是本机结果；本地Git状态不是远端同步证明。不要自动安装、pull/push或覆盖产物。

## 2. 一次完整主题课的备课卡

备课卡应包含下面各项；可以随讲解展开，不要求每次用同一种排版。

| 项目 | 应说明的内容 |
|---|---|
| 问题和意义 | 本课解决什么模型/训练/推理问题，如何服务mini-GPT或后续算法 |
| 前置与复用 | 哪些已有代码/概念直接复用，哪里出现实际基础缺口；不重复整套A/B |
| 数学与机制 | 目标函数、核心公式、数据流、参数含义；抽象概念配具体例子 |
| 输入与输出 | 路径、Shape、dtype、device、是否记录梯度，以及输出数值/文件的意义 |
| 实现框架 | 按依赖顺序拆功能块，每块写目的→输入输出→操作→API→自查；给不可执行主流程伪代码 |
| API位置 | 参数/返回值/副作用、在哪一步使用；区分函数对象、函数调用、返回对象及原地修改 |
| 核心证据 | 少量能发现真实数学/数据流错误的检查；不以loss下降或打印True单独证明正确 |
| 本次第一步 | 学生现在从哪个现有文件、哪个功能块开始写 |
| 必做与可选 | 核心实现明确；函数化、多模块、漂亮打印、额外绘图/性能优化按需 |

主题大小以可理解和可实现为准：不是一个API一节，也不是一次讲完全部Transformer。一个主题允许分讲解、手写、排错几次对话，但不在每次答疑后追加新作业。

## 3. 提示与补讲

- 从“原理/现象”到“位置、Shape/API”再到“不可执行伪代码/局部修改策略”逐级帮助，默认不提供可直接运行的答案或完整局部例子。
- 学生卡在Python语法时，解释语法本身和当前用途，例如字典键/函数对象/调用结果，不用更抽象的术语代替说明。
- 学生询问原理时，不把补讲变成额外口试关卡；保留后续复习点即可。
- 作者源码可用于对照概念与行为，不把其完整函数当模板让学生改变量名。外部练习只选适配本主题的部分，不另开平行必修课。
- 原理/源码阅读课也安排一段学生代码观察或微型对照；形式可以是数值计算、可视化或局部验证，不要求整套新工程。
- 语气可以轻松、有活力，技术内容要准确：先定义再举例，承认验证边界，不以夸赞替代反馈。

## 4. Review与验收

1. 区分静态阅读、语法解析、局部实验、完整运行、跨进程实验。没有运行的部分不能写成“测试通过”。
2. 先看数学/数据流/Shape/梯度/参数绑定，再看非核心工程细节。先定位最早阻塞，并说明后面哪些是静态发现而非实测错误。
3. 跑与修改相称的小规模检查。对已有成功验证不重复跑，除非新代码、失败或未解决的问题需要。
4. 默认由学生修复核心错误；不要为了验收重写核心算法。可在临时目录承接测试输出，保留学生检查点和代码。
5. 在明确任务与环境范围内运行正确、结果正确并体现核心概念，可以PASSED。独立熟练度、提示依赖、未实践工具分别记录，不要求固定测试数量、整张量手算或预测注释。
6. 若CPU检查通过而CUDA目标确实未验证，分别记录范围。保留待补项并继续独立主题，不伪造GPU通过，也不无限期冻结整个课程。
7. D阶段综合验收复用已有成果；P-E的因果性、标签错位、生成范围和恢复一致性是算法核心检查，不能只因文本“看起来像话”而省略。

## 5. 如何维护PROGRESS.md

每次实际教学/审阅结束以及验收完成后自动维护，已有持续授权，不再询问是否记录。

### 当前状态区

- 当前主题与实际学生文件；文件存在时及时把“待创建”改成“已有草稿”。
- 状态和验证范围：EXPLAINED是讲过，IN_PROGRESS是已开始但未通过，PASSED是明确范围内已验证；源码存在或语法解析通过不等于算法通过。
- 已通过列表保留；单次复习不撤销历史通过，只有发现真正核心缺陷才说明需复核的具体部分。
- 下一项最小动作是一件具体可执行的事；环境待补项单列，不能与已验证事实混淆。

### Session最低记录字段

日期与主题；读取/修改的相对路径；学生实际改动；执行命令或验证方法；实际输出/结论；提示依赖与待复习点；未验证范围；下一步。设备/依赖变更和Git操作仅在实际发生时记录。

- 每次追加到历史Session之后、模板之前；不覆盖旧Session或按新路径批量改写历史。
- 调整路线时同步LEARNING_PLAN.md；调整长期规则时同步AGENTS.md；普通Review不反复改课程目标。
- 本次代码若只在CPU/单进程运行，不能扩写为GPU/跨进程稳定；别人的Notebook输出不是本学生的运行证据。
- 通过但经多轮提示，应记录“经提示修正后通过”；不要在PASSED之外虚构独立熟练评分。
- 无需每次固定提出1–3个问题。真正未理解的点可保留，在后续相关任务中自然确认。

## 6. 文件与跨设备协作

- AGENTS.md：短的常驻约束与文档入口；LEARNING_PLAN.md：路线与主题目标；PROGRESS.md：唯一实际进度。
- docs/RESOURCE_MAP.md：来源、核实范围和课程映射；审查报告按日期归docs，不作为新的当前进度源。
- lessons/<小写课程ID>/：学生课程脚本/模块，outputs/放产物并保留.gitkeep；路径按脚本课程目录定位，不依赖cwd。
- projects/mini_gpt/：进入综合实现时按需使用；nanoGPT参考目录只有实际引入后才存在，不自动克隆或创建未来目录。
- 代码与进度一起由学生commit/push；另设备先pull再读取本地记录。模型等被忽略产物不保证随Git同步，不能仅因代码已pull就声称检查点也已到位。
